How your phone times a signal

Each satellite repeats its own pattern of 1,023 “chips” every millisecond. Your phone makes its own copy of the pattern and slides it in time until it lines up with what arrives. How far it had to slide is the travel time. The catch: by the time it reaches you, the signal is weaker than the background noise.

You can’t see the signal, but you can find it

At −20 dB the code is invisible in the top trace. But at the right position, 2,046 tiny agreements add up while the noise mostly cancels, so the peak stands out. Listening longer helps for the same reason.

One frequency, many satellites

Every GPS satellite transmits on the same frequency. Each one’s code is nearly unrelated to the others’, so the copy of PRN 7’s code picks out PRN 7 and ignores the rest. This sharing trick is called CDMA.

Jamming is just more noise

Drag the signal strength down to −30 dB with 1 ms of listening: the peak sinks into the noise and the phone can’t trust any position. With no measurement there is no fix: “no fresh position”.

How it works

The satellite’s code is a fixed sequence of +1s and −1s (we generate the real GPS C/A codes, which our self-test checks against the published first chips). The phone multiplies what it receives by its own copy, sample by sample, and adds up the results:

match(shift) = (1/N) · Σ received[i + shift] × copy[i] N = 2,046 samples (2 per chip) 1 chip = 1 / 1,023,000 s = 977.5 ns → 293.05 m of travel at the speed of light

When the copy is lined up, every product is +1 (plus noise), so they add up to about 1. When it is not, the products are a jumble of +1 and −1 that cancel. The codes are designed so the off-peak values are only ever −65, −1 or +63 out of 1,023.

The code repeats every millisecond, which is 300 km of travel, so the match only gives the travel time within one millisecond. The phone gets the whole milliseconds from the timing of the data the satellite sends on top of the code (a new 6-second subframe starts at known times), and from a rough idea of where it is.

Each code repeat is a fresh chance for the noise to be different, while the signal is the same. Adding K repeats makes the peak K times taller but the noise only √K times bigger. That is how the phone digs out a signal that is weaker than the noise.

What we simplified

We send the raw code with no carrier wave and no data bits, at exactly 2 samples per chip, and the satellites don’t move, so there is no Doppler shift to search for as well. A real receiver searches delay and frequency together, then keeps tracking the peak with an early–late loop (see Lab 5).
